# Personal Entity Content Hub

## What this skill does

Designs the owned-site hub that ties the person entity together: the author page as root, spokes for articles (by topic cluster), talks, books, data assets and media — each spoke linking back, so engines traverse one coherent entity instead of scattered posts.

Category: **Brand & Expert Positioning** — The person as an entity: positioning statements, speaking and book evidence, media kits and identity-answer repair.

## Inputs

- Author page (built or specced)
- The content inventory: articles, talks, books, reports, media

## Workflow

1. **Inventory and cluster** — Group all content by topic cluster matching the tier map; orphan content with no cluster is assigned or retired.
2. **Set the hub structure** — Author page -> cluster pages -> individual assets. Cluster pages carry a short canonical intro and link every asset in the cluster.
3. **Write cluster intros factually** — Each cluster opens with what the expert does in this topic, with the descriptor — cluster pages are themselves citable.
4. **Interlink by rule** — Every asset links up to its cluster and the hub; the hub links the flagship asset from every cluster. No dead ends.
5. **Maintain the map** — New content joins a cluster at publish time (checklist item); quarterly, the hub map is diffed against the live site.

## Output

A hub map (clusters x assets x links) and the publish-time linking checklist.

## Measurement

Zero orphan citable assets; every cluster reachable from the author page in 2 clicks; hub cited in identity/topic answers.

## Guardrails

- **No fake citations.** Only cite sources that exist and say what you claim they say. Never invent a mention, a quote, a ranking or a review.
- **No fabricated stats.** Every number comes from the user's own data or a named public source. If a figure cannot be verified, mark it `[verify]` and leave it out of published copy.
- **White-hat only.** No spam directories, no paid listicle placements on SEO-spam roundups, no cloaking, no hidden text, no fake reviews, no doorway pages.
- **No guarantees.** AI answer placement cannot be guaranteed. State realistic ranges and timelines; engines change without notice.
- **Entity facts stay consistent.** Use the canonical bio and descriptor verbatim wherever the entity is described; flag any surface that contradicts it.
- Skill-specific: Do not build hub pages as tag dumps. A cluster page with no written intro is a list, and lists without statements do not get cited.
